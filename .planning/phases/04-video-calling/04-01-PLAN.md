  <action>
    Create src/lib/calls.ts with the following exported functions. Use the existing `prisma` import from `@/app/lib/db`.

    1. `generateRoomName(): string` — returns a unique room name string using format `vsl-call-${Date.now()}-${randomString(8)}` where randomString produces alphanumeric characters.

    2. `createCall(callerId: number, calleeId: number): Promise<{ callId: number; roomName: string; expiresAt: Date }>` — validates callerId !== calleeId, checks both users exist via prisma.user.findUnique, calls checkBusy() for both participants, creates a CallSession with state RINGING, expiresAt = now + 30 seconds, returns callId/roomName/expiresAt.

    3. `acceptCall(callId: number, userId: number): Promise<{ roomName: string; callerToken: string; calleeToken: string }>` — uses prisma.callSession.updateMany with where: { id: callId, calleeId: userId, state: 'RINGING', expiresAt: { gt: new Date() } }, data: { state: 'ACTIVE', acceptedAt: new Date() }. If updateMany.count !== 1, throw new Error('Call unavailable'). After successful transition, import generateLiveKitToken from src/lib/livekit.ts and generate tokens for both caller and callee. Return roomName and both tokens.

    4. `rejectCall(callId: number, userId: number): Promise<void>` — atomic updateMany transitioning from RINGING to REJECTED where calleeId matches userId.

    5. `cancelCall(callId: number, callerId: number): Promise<void>` — atomic updateMany transitioning from RINGING to CANCELLED where callerId matches.

    6. `endCall(callId: number, userId: number): Promise<void>` — atomic updateMany transitioning from ACTIVE to ENDED where (callerId === userId OR calleeId === userId), sets endedAt = now.

    7. `checkBusy(userId: number): Promise<boolean>` — returns true if user has any CallSession with state RINGING or ACTIVE.

    8. `expireRingingCalls(): Promise<number>` — finds all RINGING calls where expiresAt < now, transitions them to MISSED, returns count of expired calls.

    All functions must use Prisma transactions (prisma.$transaction) where multiple operations are needed. Use updateMany for atomic state transitions to prevent races. Never accept userId from the caller for identity — the function parameter userId must be validated against the JWT-authenticated user at the API layer (API routes do this, state machine functions just enforce calleeId/callerId matching).
  </action>
