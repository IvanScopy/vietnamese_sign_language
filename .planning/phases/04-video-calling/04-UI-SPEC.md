## Product Surface

Phase 4 adds real 1:1 video calling for registered users. The first screen for this phase must be the call workflow itself, not a marketing or demo page: contact selection or direct call entry, outgoing ringing, incoming call, active call, and ended/missed/busy states.

Mobile and web should feel native to their platform, but they must share the same visible call state model and copy. Mobile is primary for camera, haptics, and background incoming-call handling; web is a real user-facing call surface with foreground/in-browser notification behavior.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status-dot gaps, subtitle metadata spacing |
| sm | 8px | Compact control spacing, pill padding, video overlay gaps |
| md | 16px | Default screen padding, button groups, call sheet padding |
| lg | 24px | Ringing screen content groups, modal/sheet padding |
| xl | 32px | Major vertical breaks between caller identity and actions |
| 2xl | 48px | Empty-state and error-state top spacing |
| 3xl | 64px | Wide desktop max spacing around the call canvas |

Exceptions: icon-only controls and incoming-call actions must use a minimum 44px touch target on mobile and 40px target on web. Active call video tiles may use 12px internal padding where 16px would crowd subtitles.

## Typography

Use exactly these four text sizes for Phase 4 UI surfaces:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Rules:

- Use Display only for caller name or call-ended headline on ringing/ended screens.
- Use Heading for active call sheet titles, permission errors, and empty states.
- Use Body for subtitles, sign text, transcript preview, and error bodies.
- Use Label for buttons, status pills, timestamps, role labels, and notification metadata.
- Do not scale font size with viewport width.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #101010 | Active video canvas, remote video background, local preview background |
| Secondary (30%) | #FFFFFF | Bottom sheets, ringing panels, transcript save prompt, web side panels |
| Accent (10%) | #16A34A | Accept call, active signer status, Confirm & Play, connected state |
| Destructive | #DC2626 | Reject call, End call, Cancel outgoing call, discard unsaved transcript |

Accent reserved for: Accept call, active signer status, Confirm & Play, connected call status, and successful transcript-saved confirmation. Do not use the accent for every button.

Role and status colors:

- Speaking user/subtitles: #2563EB, used only for speaker role badges and speech subtitle source labels.
- Manual/demo/unclear state: #F59E0B, used for low-confidence sign text, fallback/manual labels, and permission warnings.
- Disabled/offline: #6B7280, used for unavailable controls and disconnected status labels.
- Busy/missed: #7C3AED, used for busy or missed-call state icons only.

No flashing visual effects are allowed. Visual incoming-call affordances must use stable color, iconography, haptics, and readable text labels.

## Layout Contract

### Mobile

- Outgoing ringing screen: full-screen caller/callee identity, call status text, Cancel button at the bottom, and a compact connection status line.
- Incoming call screen: full-screen caller identity, large Accept and Reject controls anchored in the lower third, visual/haptic affordance, no flashing.
- Active call screen: remote video fills the screen; local preview sits as a small draggable or fixed top-corner tile with a stable aspect ratio.
- Translation overlays sit at the bottom of the video above call controls. Use at most two visible lines for live subtitles and at most two lines for sign draft text before expansion.
- Call controls occupy a bottom control bar: mute mic, camera on/off, switch camera, subtitles/sign overlay toggle if needed, and End call.
- Transcript save prompt appears as a bottom sheet after call end or from an in-call Save action; it must make clear that only text is saved.

### Web

- Active call canvas uses a two-column layout on tablet/desktop: primary remote video area plus a right-side panel for call status, transcript draft, and controls. On narrow widths, collapse to the mobile stacked layout.
- Web foreground incoming call uses an in-app modal/sheet with Accept and Reject; browser notification may deep-link to the same incoming screen when permission is available.
- Keep web controls visually consistent with mobile labels and icons, but do not force pixel-perfect parity.

## Interaction Contract

- Call lifecycle states are: idle, outgoing ringing, incoming ringing, connecting, active, busy, missed, rejected, cancelled, ended, failed.
- Incoming calls time out after 30 seconds and move to missed state.
- Caller cancellation before acceptance dismisses the receiver prompt or marks it unavailable.
- Either participant pressing End ends the call for both participants.
- If the user is already in a call, show a lightweight busy notification to the receiver and return busy to the caller.
- LiveKit room join happens only after Accept.
- Video remains the primary surface during active calls.
- Sign recognition output uses draft -> Confirm -> Confirm & Play. Do not auto-play TTS from raw recognition output.
- Hearing-user speech appears as live subtitles for the deaf participant.
- Low-confidence sign recognition below 0.60 shows an unclear/manual correction state before confirmation.
- Transcript saving is explicit. Store text only; never imply that audio or video is retained.
- Permission errors for camera, microphone, notifications, or network setup must keep the user on a recoverable screen with a visible retry path.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Start video call |
| Empty state heading | No active call |
| Empty state body | Choose a registered contact to start a 1:1 video call. |
| Error state | Call could not connect. Check camera, microphone, and network access, then try again. |
| Destructive confirmation | End call: End this call for both people? |

Additional required copy:

- Incoming call heading: `Incoming video call`
- Incoming call actions: `Accept`, `Reject`
- Outgoing call status: `Ringing...`
- Timeout state: `Missed call`
- Busy state: `This person is already in a call.`
- Cancelled state: `Call unavailable`
- Transcript save prompt: `Save text transcript?`
- Transcript privacy body: `Only confirmed text will be saved. Audio and video are not recorded.`
- Sign draft action: `Confirm`
- Sign TTS action: `Confirm & Play`
- Permission action: `Open settings`
- Retry action: `Try again`

Destructive actions:

- `End call`: red end-call control; confirmation required on web and optional native bottom confirmation on mobile if accidental taps are likely.
- `Reject call`: red incoming-call action; no confirmation.
- `Cancel call`: red outgoing-call action; no confirmation.
- `Discard transcript`: confirmation required with copy `Discard this text transcript?`

## Accessibility Contract

- All icon-only buttons must expose semantic labels/tooltips.
- Color must not be the only status indicator; pair role/status colors with text labels such as `Signer`, `Speaker`, `Unclear`, `Manual`, `Connected`, `Busy`, and `Missed`.
- Incoming call feedback must include visual treatment and haptic/vibration support on mobile.
- Do not use flashing, pulsing strobes, or rapid animation for call notifications.
- Subtitle overlays must maintain contrast against video by using a #101010 scrim at 72% opacity behind text.
- Touch targets must be at least 44px on mobile where space allows.
- Text must not overflow inside call buttons, status pills, overlays, or transcript sheets.
