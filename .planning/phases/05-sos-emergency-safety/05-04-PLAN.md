<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile/Web client → POST /api/sos/alerts | Untrusted location and idempotency inputs cross into safety-critical send path. |
| Backend → Twilio | Provider credentials and SMS body leave the app server. |
| Backend → emergency contacts | Sensitive location is sent only to configured contacts loaded by server. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08 | Spoofing/Elevation | `POST /api/sos/alerts` | mitigate | Use `getAuthenticatedUser`; derive sender from JWT; ignore body userId and recipient lists. |
| T-05-09 | Tampering | `src/app/lib/sos.ts` contact fanout | mitigate | Load active contacts by authenticated user from Prisma; no client-selected recipients. |
| T-05-10 | Denial of Service | Twilio SMS sends | mitigate | Idempotency key prevents duplicate sends from retries; provider failures are recorded and routed to fallback. |
| T-05-11 | Information Disclosure | SMS body | mitigate | Include only D-12 emergency content and location label; no medical profile or long health-record payload. |
| T-05-SC | Tampering | npm/pub package installs | mitigate | Depends on 05-01 blocking package checkpoint for `[ASSUMED]` packages. |
</threat_model>
