<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile OS → app | Permission and GPS results can be denied, stale, inaccurate, or unavailable. |
| App → backend API | Location and fallback payloads are untrusted until backend validates them. |
| App storage → API auth | Bearer token must be sent only to configured backend URL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-16 | Information Disclosure | `SosLocationService` | mitigate | Collect location only inside SOS flow; expose quality labels and avoid extra tracking. |
| T-05-17 | Denial of Service | GPS acquisition | mitigate | 5-second current GPS budget with last-known/unavailable fallback so SOS is not blocked. |
| T-05-18 | Tampering | `SosApiService` request body | mitigate | Client sends only location/fallback inputs; backend plans validate and owner-check all writes. |
| T-05-SC | Tampering | npm/pub package installs | mitigate | Depends on 05-01 blocking package checkpoint for `[ASSUMED]` packages. |
</threat_model>
