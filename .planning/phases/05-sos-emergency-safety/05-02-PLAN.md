<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API validators | Untrusted SOS, location, fallback, and contact payloads enter backend routes. |
| API → Database | Sensitive location and emergency contact data become durable records. |
| Twilio → API callback | External provider status callbacks can be forged unless later signature validation is enforced. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02 | Tampering | `CreateSosAlertSchema` | mitigate | Schema rejects client-supplied recipient/contact/userId lists; backend will load contacts by authenticated user. |
| T-05-03 | Information Disclosure | `SOSAlert` location fields | mitigate | Store only coordinates, accuracy, label, timestamp, and generated SMS body required for SOS; no medical payload fields. |
| T-05-04 | Repudiation | `SosAlertAttempt` | mitigate | Durable per-recipient attempt rows record provider SID/status/error and native composer opened/failed states. |
| T-05-SC | Tampering | npm/pub package installs | mitigate | Depends on 05-01 blocking package checkpoint for `[ASSUMED]` packages. |
</threat_model>
