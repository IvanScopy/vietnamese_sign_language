<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User gesture → SOS send | Accidental activation must be prevented by hold/countdown/cancel. |
| Flutter app → OS SMS/dialer | Native handoffs leave app control and cannot prove completion. |
| FCM payload → navigation | Notification data is untrusted display/routing input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-19 | Repudiation | native SMS fallback UI | mitigate | UI and service record only composer opened/failed, never native sent. |
| T-05-20 | Safety/Denial | SOS activation | mitigate | 2-second hold plus 5-second countdown and large cancel action prevent accidental sends while preserving emergency speed. |
| T-05-21 | Elevation/Safety | `tel:115` handoff | mitigate | `Gọi 115` uses explicit user tap and `tel:115` dialer only; no automatic call. |
| T-05-22 | Information Disclosure | SOS notification routing | mitigate | Treat FCM data as routing/status only; backend owns sensitive send details. |
| T-05-23 | Accessibility | SOS visual state | mitigate | Stable color/icon/text/haptics; no strong flashing, strobe, or rapid pulsing. |
| T-05-SC | Tampering | npm/pub package installs | mitigate | Depends on 05-01 blocking package checkpoint for `[ASSUMED]` packages. |
</threat_model>
