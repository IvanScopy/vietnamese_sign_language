## Product Surface

Phase 5 adds safety-critical SOS surfaces on mobile only. The entry point appears on the existing home screen button stack and must not be added as an app-wide floating control.

The SOS flow is urgent but controlled: home-screen entry, 2-second hold gesture, 5-second full-screen countdown, cancel state, location/SMS status states, native SMS fallback state, and `Gọi 115` dialer handoff. The interface must never claim more certainty than the platform gives: provider SMS success may say `Đã gửi`, native SMS fallback must say `Đã mở SMS, chờ người dùng gửi`, and approximate or stale location must be labeled honestly.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status metadata gaps, progress ring label spacing |
| sm | 8px | Compact status rows, haptic/accessibility labels, inline warning copy |
| md | 16px | Default screen padding, button groups, status cards |
| lg | 24px | Home SOS block padding, countdown content groups, failure-state groups |
| xl | 32px | Separation between emergency title, countdown, and action controls |
| 2xl | 48px | Lower-third action spacing and post-send `Gọi 115` separation |
| 3xl | 64px | Large full-screen warning breathing room on taller devices |

Exceptions: hold target and primary emergency actions must be at least 64px high; icon-only status affordances must keep a minimum 44px touch target; countdown progress ring may use fixed 160px diameter on compact phones and 192px on larger phones.

## Typography

Use exactly these four text sizes for Phase 5 UI surfaces:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Rules:

- Use Display only for `SOS khẩn cấp`, the countdown number, and terminal state headlines such as `Đã hủy` or `Đã gửi`.
- Use Heading for location/SMS provider status headings, no-contact warnings, and `Gọi 115`.
- Use Body for explanatory Vietnamese copy, location quality labels, and error recovery guidance.
- Use Label for buttons, status chips, timestamps, contact counts, and platform-handoff labels.
- Do not scale font size with viewport width. Text must wrap within buttons and status cards instead of shrinking below 14px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Home screen, neutral status surfaces, resolved/cancelled screens |
| Secondary (30%) | #F3F4F6 | Status cards, location/SMS detail panels, home SOS secondary context |
| Accent (10%) | #DC2626 | SOS entry, hold progress, countdown warning, emergency status icon, `Gọi 115` |
| Destructive | #B91C1C | `Hủy` during countdown and destructive cancel confirmation treatment only |

Accent reserved for: home-screen SOS entry, hold-to-activate progress, countdown background/action emphasis, active SOS status iconography, provider/native SMS emergency status indicators, and the `Gọi 115` action. Do not use red accent for ordinary navigation, profile contact management, or non-emergency buttons.

Semantic colors:

- Success/provider sent: #16A34A for `Đã gửi` only when backend provider confirms send/accepted status.
- Warning/native fallback/approximate location: #F59E0B for `Đã mở SMS`, `vị trí gần đúng`, `vị trí cuối cùng đã biết`, no contacts, and permission warnings.
- Neutral/working: #2563EB for `Đang lấy vị trí` and `Đang gửi`.
- Disabled/offline: #6B7280 for unavailable controls and unavailable location details.

No strong flashing, strobe, or rapid pulsing is allowed. Emergency urgency must come from stable red treatment, large type, iconography, countdown motion, and haptics.

## Layout Contract

### Home Screen Entry

- Add one `ElevatedButton.icon` or visually stronger Material button to the existing logged-in home-screen button column in `mobile/lib/main.dart`.
- Place the SOS entry below primary communication actions but above lower-priority history/navigation links so it is visible without scrolling on common phones.
- Label: `SOS khẩn cấp`. Icon: `Icons.sos`, `Icons.warning_rounded`, or closest Material emergency icon available.
- Button height: minimum 64px. Horizontal padding: 32px. Red accent background with white icon/text.
- Supporting line below the button: `Nhấn giữ 2 giây để bắt đầu`. This line is informational, not a separate action.

### Hold Gesture

- Pressing the SOS entry does not send immediately. The user must hold for 2 seconds.
- While holding, show a stable circular or linear progress indicator around/inside the SOS button and text `Giữ để gửi SOS`.
- On hold completion, navigate to the full-screen countdown state. On release before 2 seconds, reset progress without error.
- Provide haptic feedback at hold start and hold completion; pair it with visible progress for deaf users and users who disable vibration.

### Countdown Screen

- Use a full-screen warning state with SafeArea. Dominant background may become #DC2626 only during the active 5-second countdown.
- Center stack: emergency icon, `SOS khẩn cấp`, countdown number, and body copy `Tin nhắn khẩn cấp sẽ được gửi sau 5 giây.`
- Lower third: large `Hủy` action, minimum 64px high, high contrast, reachable by thumb.
- Countdown must be readable without relying on animation: show numeric seconds and a progress ring/bar.
- Gentle rhythmic haptics may occur once per second; do not pair with flashing visuals.

### Cancelled State

- If cancelled during countdown, show a neutral full-screen state for 2-3 seconds, then return to home.
- Copy: headline `Đã hủy`; body `SOS chưa được gửi.`
- Do not create a backend SOS alert when the flow is cancelled before the countdown finishes.

### Location And Sending Status

- After countdown finishes, show a status screen, not a modal.
- Status sequence: `Đang lấy vị trí` -> `Đang gửi` -> `Đã gửi` or `Đã mở SMS` -> `Gọi 115`.
- Each state must include an icon, headline, short body copy, and a status detail card.
- Location card states:
  - Current GPS available: `Đã lấy vị trí` plus coordinate/map-link preview.
  - Permission denied: `Không có quyền vị trí`; body `SOS vẫn sẽ được gửi không kèm vị trí.`
  - GPS timeout: `Chưa lấy được vị trí`; body `SOS sẽ được gửi trước. Vị trí sẽ được cập nhật nếu có sau.`
  - Low accuracy: label `vị trí gần đúng`.
  - Last-known location: label `vị trí cuối cùng đã biết`.
- Contact card states:
  - Contacts configured: `{n} liên hệ khẩn cấp`.
  - No contacts: `Chưa có liên hệ khẩn cấp`; body `Bạn vẫn có thể gọi 115.`

### SMS Provider And Native Fallback States

- Provider path:
  - Working: `Đang gửi tin nhắn`.
  - Success: `Đã gửi`.
  - Partial or per-contact mixed result: `Một số tin nhắn chưa gửi được`; show per-contact status rows when available.
- Native fallback path:
  - Composer opened: `Đã mở SMS, chờ người dùng gửi`.
  - Composer failed: `Không mở được SMS`; show copyable message body and keep `Gọi 115`.
- Never display `Đã gửi` for native SMS composer handoff unless provider delivery actually confirmed it.
- If the phone has no network, show `Không có mạng`; body `Ứng dụng sẽ mở SMS hoặc trình gọi khi có thể.`

### 115 Dialer Handoff

- After SMS is sent or initiated, show a large primary action `Gọi 115`.
- Tapping `Gọi 115` opens the system dialer with `115`; the app must not automatically place the call.
- Supporting copy: `Bạn sẽ xác nhận cuộc gọi trong ứng dụng Điện thoại.`
- Secondary action after dialer handoff: `Đóng` returns home. Keep `Gọi 115` visible if the user returns without calling.

## Interaction Contract

- SOS entry exists only on the mobile home screen in Phase 5.
- Activation requires a 2-second press-and-hold, then a 5-second countdown.
- Releasing before hold completion cancels only the hold preview and stays on home.
- `Hủy` during countdown stops the SOS and shows `Đã hủy` for 2-3 seconds before returning home.
- Location permission is requested inside the SOS flow. Denial does not block sending.
- GPS wait budget is 5 seconds. If unavailable, send without location and update later if location becomes available.
- Backend provider SMS is attempted first. Native SMS composer is fallback for backend failure, network failure, or provider unavailability.
- Send attempts go to all configured emergency contacts simultaneously; do not expose recipient selection at SOS time.
- If there are no emergency contacts, continue to the status screen with no-contact warning and `Gọi 115`.
- The visible state model is: idle, holding, countdown, cancelled, locating, sending provider SMS, opening native SMS, sent, partial failure, failed, dialer handoff, closed.
- All failure states must keep at least one next action visible: `Mở SMS`, `Sao chép nội dung`, `Gọi 115`, `Thử lại`, or `Đóng`.
- Do not add receiver acknowledgement, escalation chains, medical profile payloads, contact prioritization, or app-wide floating SOS behavior in this phase.

- `Đóng`: allowed after status/dialer handoff; no confirmation.

## Accessibility Contract

- All icon-only buttons must expose semantic labels/tooltips in Vietnamese.
- Color must not be the only status indicator; every state needs text and icon pairing.
- Provide visible hold/countdown progress for deaf users and users who cannot perceive haptics.
- Use haptics as reinforcement only: short feedback on hold start, hold completion, countdown ticks, send success/fallback, and failure.
- Do not use strong flashing, strobe, rapid pulsing, or alternating full-screen color effects.
- Touch targets must be at least 44px; emergency primary actions must be at least 64px high.
- Countdown number, `Hủy`, `Gọi 115`, and send state headlines must remain readable at small phone widths without clipping.
- Native fallback and location quality labels must be explicit and not hidden behind tooltips.
- Screen readers must announce state changes: countdown start, countdown remaining, cancelled, location unavailable, provider sent, native SMS opened, and dialer handoff.
