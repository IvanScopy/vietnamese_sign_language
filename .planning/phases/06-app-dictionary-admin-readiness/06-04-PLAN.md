<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin clients -> `/api/admin/**` | All admin requests are untrusted until authenticated and role-checked server-side. |
| Admin broadcast body -> notification recipients | Targeting input can send messages to unintended users. |
| SOS logs -> admin responses | Emergency logs may contain sensitive location/contact status data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Elevation of Privilege | Admin route handlers | mitigate | Call `requireAdminRole` in every admin route before body parsing/mutation. |
| T-06-03 | Information Disclosure | Admin user/SOS responses | mitigate | Use explicit Prisma `select`; omit password, token, provider secret, and raw sensitive fields. |
| T-06-04 | Repudiation | Sensitive admin mutations | mitigate | Write `AdminAuditLog` rows inside the same transaction as state changes. |
| T-06-09 | Tampering | Broadcast targeting | mitigate | Validate target groups, require server-generated preview id/message hash/target-count echo before confirm, and audit confirmed sends. |
| T-06-16 | Elevation of Privilege | Admin user deactivation | mitigate | Invalidate refresh tokens when `isActive=false`, reject inactive users in shared APIs, and prevent last-active-Super-Admin lockout. |
| T-06-10 | Information Disclosure | Draft dictionary rows | mitigate | Expose drafts only through admin dictionary routes with role checks. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages. |
</threat_model>
