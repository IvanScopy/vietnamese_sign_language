## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, caption gaps, progress bar radius |
| sm | 8px | Compact element spacing, icon-to-label gaps, card inner row gaps |
| md | 16px | Default element spacing, card padding, mobile screen padding |
| lg | 24px | Page padding, section padding, modal padding |
| xl | 32px | Layout gaps, heading-to-content spacing, dictionary detail spacing |
| 2xl | 48px | Major section breaks, empty state vertical rhythm |
| 3xl | 64px | Large mobile actions, hero-free app shell gutters, emergency actions |

Exceptions: mobile and web icon-only controls must be at least 44px square; Flutter primary touch targets must be at least 48px high; emergency actions must be at least 64px high; dictionary video areas use fixed aspect ratio `16 / 9`; admin tables may use 12px row gaps only inside dense table cells.

## Typography

Use exactly these four text sizes across web/admin/mobile unless platform defaults are needed for native controls:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 | 1.3 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Rules:

- Use only weights 400 and 600.
- Use 12px only for timestamps, helper text, table metadata, and status captions already present in call/history UI.
- Do not use negative letter spacing. Uppercase labels may use `0.05em` only for compact status labels such as incoming-call headings.
- Vietnamese dictionary terms use Heading or Display size on detail pages, never all caps.
- Admin tables use Body for row values and Label for column headers/actions.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | App background, web/mobile primary surfaces, dictionary detail background |
| Secondary (30%) | `#F3F4F6` | Cards, admin table backgrounds, app shell nav/sidebar, empty-state panels, metadata blocks |
| Accent (10%) | `#2563EB` | Primary non-emergency CTA, selected navigation item, focused search input, active filters, progress/loading state |
| Destructive | `#DC2626` | SOS, reject/end call, deactivate user, delete/unpublish confirmation, failed/error states |

Accent reserved for: primary submit buttons, selected app navigation, active category/filter chip, focused search border, dictionary video loading/progress state, web recognition camera-start action, admin save/publish action. Do not use accent for every link, icon, divider, or decorative background.

Additional semantic colors:

| Role | Value | Usage |
|------|-------|-------|
| Success | `#16A34A` | Accept call, sent/connected/published status, successful save confirmation |
| Warning | `#F59E0B` | Draft/needs-review, native SMS fallback, partial location, pending upload/review |
| Text primary | `#101010` | Main readable text |
| Text secondary | `#6B7280` | Helper text, timestamps, secondary labels |
| Border | `#E5E7EB` | Card, table, input, and divider borders |

Color rules:

- Keep SOS red visually isolated; normal app navigation must not use red.
- No flashing effects. Use stable color, progress, text, haptics, and live-region updates for status.
- Admin role/status chips use semantic fills at 10% opacity with readable text color.
- Video/camera surfaces may use dark controls (`rgba(16,16,16,0.9)`) only inside media areas.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Search signs |
| Empty state heading | No signs found |
| Empty state body | Try another Vietnamese word or choose a category. |
| Error state | We could not load this content. Check your connection and try again. |
| Destructive confirmation | Deactivate user: This user will lose access until reactivated. Confirm deactivation? |
| Destructive confirmation | Unpublish sign: This sign will disappear from the user dictionary. Confirm unpublish? |
| Destructive confirmation | Delete draft sign: This draft will be permanently removed. Confirm delete? |
| Destructive confirmation | Send broadcast: Preview this message and target count before sending. Send broadcast now? |
| Destructive confirmation | Close SOS incident: Mark this SOS incident as reviewed? |

Tone:

- Use short, concrete interface copy. Prefer action verbs: `Search signs`, `Start camera`, `Save changes`, `Publish sign`, `Preview broadcast`.
- User-facing web/mobile copy should be supportive and plain. Admin copy should be operational and precise.
- Error copy must name the problem and the next step; do not expose stack traces, tokens, storage keys, or provider internals.
- Web SOS copy must be honest: browser SOS is informational only and cannot replace mobile SMS, dialer, and reliable location flows.

## Surface Contracts

### Mobile App Shell

- Replace the current button-list home with a Flutter Material 3 tab shell.
- Main tabs are exactly `Communicate`, `Dictionary`, `SOS`, and `Profile`.
- Use `NavigationBar` with an `IndexedStack` so tab state is preserved.
- `SOS` remains a top-level tab and uses red icon/label only for that tab.
- Conversation history lives under `Communicate` or `Profile`, not a top-level tab.
- All tappable controls are at least 48px high; icon-only controls expose semantic labels.
- Account states: logged out, logged in, session expired, offline, and loading must each have a visible state.
- Session-expired copy: `Your session expired. Log in again to continue.`

### Web App Shell

- Replace API-only home with a protected product app shell.
- User navigation includes `Dictionary`, `Recognition`, `Calls`, `Profile`, and `Notifications`.
- Desktop uses a left sidebar or persistent header with constrained content width; mobile uses a compact top bar plus bottom or drawer navigation.
- `/admin` is a separate surface and must not share user navigation chrome.
- Web SOS is an informational page or profile/help affordance only; it must not imply browser emergency parity.
- Responsive breakpoints: below 768px use one-column layouts; 768px and above may use sidebar plus content; 1024px and above may use two-pane admin/content layouts.

### Dictionary

- Dictionary landing combines a prominent Vietnamese search input with a category/topic grid.
- Search input appears above categories on mobile and desktop.
- Result cards show thumbnail, Vietnamese sign text, category/topic, and status only on admin surfaces.
- User-facing results show published entries only. Draft and needs-review entries never appear to users.
- Detail page includes 16:9 video, play/pause/seek, replay, speed choices `0.5x`, `0.75x`, `1x`, fullscreen where supported, Vietnamese text, category/topic, tags, updated date, and related signs.
- Video loading state: stable progress indicator with copy `Loading video...`.
- Video error state: `This video could not be loaded. Try again later.`
- Empty categories show `No published signs in this category yet.`

### Web Recognition

- Camera permission starts from an explicit `Start camera` action.
- Before camera starts, show what will happen in one sentence: `Use your webcam to recognize Vietnamese signs.`
- If camera is unavailable, show `Camera requires HTTPS, localhost, and a supported browser.`
- If permission is denied, show `Camera permission was denied. Allow camera access in your browser settings and try again.`
- Always provide `Stop camera`; stop media tracks when leaving the page.
- Recognition output uses a high-contrast text panel with confidence/status text; do not rely on color alone.

### Admin

- `/admin` uses a dense operational layout: sidebar navigation, page title, toolbar, filter/search row, table/list, and detail drawer or form.
- Admin sections: Users, Dictionary, Lesson placeholders, SOS logs, Broadcasts, Audit logs.
- Role labels: `Super Admin`, `Content Admin`, `Support Admin`.
- User table must not display passwords, refresh tokens, raw emergency contact secrets, or sensitive provider payloads.
- Sensitive actions use confirmation dialogs with action-specific copy from the Copywriting Contract.
- Broadcast flow is two step: compose/select target, then preview with target count and confirm.
- Dictionary admin status chips: `Published` success, `Draft` neutral, `Needs review` warning, `Unpublished` neutral.
- SOS log review uses status, timestamp, contact/send outcome, location label, and review action. Basic stats only; no advanced analytics.

### Calls And Existing Media Surfaces

- Preserve existing call color semantics: accept/connected `#16A34A`, reject/end/failed `#DC2626`, connecting/fallback `#F59E0B`.
- Call controls remain 44px minimum for icon buttons and 48px for text buttons where space allows.
- Translation overlays stay dark-on-media or white panels as already implemented; text must remain readable over video.

## Accessibility And Interaction Rules

- Meet WCAG contrast expectations for text and controls.
- Every icon-only action needs an accessible label.
- Do not communicate status through color alone; pair color with icon and text.
- Keyboard access is required on web: visible focus, tab order follows visual order, dialogs trap focus, Escape closes non-destructive modals.
- Mobile supports text scaling without clipping at common accessibility sizes.
- Use `aria-live` or equivalent semantic live region for camera, recognition, upload, SOS, and broadcast-send status changes.
- Loading states must not shift layout more than one row/card height.
- Offline/network failures must leave the user on the current surface with retry or next-step copy.
